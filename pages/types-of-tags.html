Types of HTML Tags

1. Semantic vs Non-Semantic Tags

A semantic tag clearly describes its purpose to both the browser and the developer. A non-semantic tag says nothing about its content.

Semantic Non-Semantic
<header><div>
<nav><span>
<main>These carry no inherent meaning.
<article>
<section>
<footer>
<form>
<table>
 
/* Prefer semantic markup — it improves SEO and accessibility */
<article>
  <header><h2>Post Title</h2></header>
  <p>Post content...</p>
</article>

2. Block vs Inline Tags

Block-level elements start on a new line and take the full available width. Inline elements sit inside a line of text; width and height are ignored.

Block elements (each on its own line):

<div> — generic block container
<p> — paragraph
<h1> – <h6> — headings
<ul>, <ol>, <li> — lists
<table>, <form>, <section>...

Inline elements (flow inside text):

This sentence contains <span> <a> <strong> and an inline image — they all sit on the same line. 
/* Any element's display type can be overridden with CSS */
span { display: block; }
div  { display: inline; }

3. Container Tags vs Empty (Void) Tags

Container tags have an opening and closing tag, and can hold child elements. Void/empty tags are self-closing and cannot have children.

Container: <div>, <section>, <article>, <ul>, <table> ...
Void / Empty: <img>, <input>, <br>, <hr>, <meta>, <link> ... 
/* Container — wraps other elements */
<div>
  <p>I am a child.</p>
</div>

/* Void — no closing tag / no children */
<img src="photo.jpg" alt="A photo">
<input type="text" placeholder="Enter name">

Note: The <p> tag is not a container for block-level elements — nesting a <div> or <h3> inside a <p> is invalid HTML.
